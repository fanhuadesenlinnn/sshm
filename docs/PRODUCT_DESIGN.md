# sshm 产品设计文档

状态：v4.0.0 产品基线已实施，持续维护

本文档用于持续记录 sshm 的产品目标、用户需求、产品边界和体验设计。访谈中的每项已确认决策会即时写入；尚未确认的内容不会被当作最终需求。

## 当前产品事实

- sshm 是一个供个人使用的跨平台命令行 SSH 主机管理工具。
- 当前提供命令行模式、交互式工作台和主机选择器。
- 当前核心能力包括主机管理、标签、收藏与最近连接、连接测试、远程执行、文件传输、SSH 配置导入导出、密码库和托管密钥。
- 当前默认采用 Go 原生 SSH 客户端，并使用主密码保护保存的 SSH 密码和托管私钥。
- 当前正式发布提供 Linux、macOS 和 Windows 的 amd64/arm64 制品。

## 已观察到的产品信号

- 产品明显重视本地优先、单文件配置、低部署成本和跨平台。
- 产品正在从“SSH 配置快捷入口”发展为“主机、认证和批量运维工作台”。
- 现有能力范围扩张较快，README、帮助、实现和测试之间已经出现漂移。
- 安全与便捷之间存在多个尚未明确的产品取舍，例如文件私钥、主机信任、批量变更确认和密码库解锁时机。

## 待确认的核心问题

主要产品边界已确认。后续通过实现、验收和实际使用反馈持续调整细节。

## 目标用户

### 核心用户

需要管理约 5～100 台服务器的个人开发者或个人运维使用者。

### 用户特征

- 经常通过 SSH 连接和操作多台服务器。
- 认为手写、记忆和维护大量 SSH 配置较麻烦。
- 需要比原生 SSH 配置更直观的主机组织、凭据管理和批量操作能力。
- 不需要完整堡垒机、团队协作平台或企业资产管理系统。

### 当前产品边界

- sshm 是个人本地工具，不面向团队协作场景。
- 主机清单、收藏、最近使用、密码和密钥均属于个人数据。
- 产品不建设账号系统、团队空间、共享主机清单、权限审批、集中审计或团队凭据库。
- sshm 暂不以企业级堡垒机和大型资产管理为核心方向。

## 核心用户旅程

以下旅程按产品优先级排序：

### 1. 快速找到并连接目标主机

核心用户能够通过别名、标签、搜索、收藏或最近使用快速定位主机，并在尽量少的交互步骤内建立可靠的 SSH 会话。

### 2. 安全、简单地管理密码和密钥

核心用户能够理解当前主机使用的认证方式，安全保存、更新、绑定和撤销凭据，并在失败时得到明确的恢复指引。

### 3. 对多台主机执行批量操作

核心用户能够选择一组主机，确认影响范围后，批量执行命令、部署密钥或传输文件，并清晰看到逐台结果和失败原因。

## 批量操作范围

### 产品承诺

- 支持面向目标集合的一次性批量命令执行。
- 支持批量部署、验证和撤销 SSH 公钥。
- 支持面向目标集合的一次性文件推送与拉取。
- 执行前展示目标范围和动作内容，并默认要求确认。
- 执行中展示进度，执行后展示逐台结果、失败原因和可重试目标。

### 明确非目标

- 不提供持续部署流水线。
- 不提供任务编排、依赖图或工作流引擎。
- 不提供定时任务与后台常驻调度。
- 不提供期望状态收敛或配置管理。
- 不以替代 Ansible、SaltStack 等自动化运维工具为目标。

## 远程操作确认策略

### 默认无需确认

- 单主机交互连接。
- 单主机 `ping` 或其他只读连接诊断。
- 单主机拉取文件或目录，前提是不覆盖本地已有内容。
- 仅查看本地配置、主机详情、标签、收藏和最近使用。

### 默认需要确认

- 单主机远程命令执行。
- 单主机推送文件或目录。
- 单主机部署、撤销或修改远端公钥。
- 所有多主机操作，无论其读取或写入性质。
- 任何覆盖现有文件或目录的传输。

### 确认内容

- 展示动作类型和关键参数。
- 多主机操作展开展示具体目标主机，不仅展示标签或数量。
- 写入与覆盖操作展示源、目标和覆盖范围。
- 密钥操作展示密钥名称和远端变更类型。

### 显式跳过

- `--yes` 仅跳过当前一次操作的普通执行确认。
- `--yes` 不跳过主机身份验证、主密码输入或其他安全控制。
- 不提供永久关闭确认的设置。
- 非交互环境中，需要确认但未提供 `--yes` 的操作应明确失败，而不是等待输入或默认同意。

## 批量命令输出模型

### 输出目标

- 默认输出优先服务核心用户直接阅读，不以机器可读 JSON 为主要目标。
- 用户能够快速看出每段输出属于哪台主机。
- 无论是否展示远程命令详情，结束时都必须明确展示成功和失败主机及 IP。

### 详细结果模式

适合 `ls -ailh`、查看配置、查看服务状态等用户希望直接阅读远程输出的命令。

- 详细结果模式是批量命令的默认输出模式。
- 每台主机开始输出前展示别名、IP 和命令。
- 紧接着完整展示该主机的远程命令输出。
- 一台主机输出完成后再展示下一台主机，避免不同主机内容交错。
- 远程命令没有输出时，也展示该主机的成功或失败状态。

示例：

```text
prod-web-01 (10.0.0.11)
$ ls -ailh
<命令输出>

prod-web-02 (10.0.0.12)
$ ls -ailh
<命令输出>
```

### 简洁状态模式

适合执行时间较长、输出较多或用户不关心远程输出内容的命令。

- 用户显式使用 `--quiet` 启用简洁状态模式。
- 程序不根据命令内容、输出大小或耗时自动切换输出模式。
- 不展示完整远程标准输出。
- 每台主机只展示 IP、当前阶段和最终成功或失败状态。
- 失败主机仍展示失败阶段、原因、建议和重试命令。
- 成功主机不展开无关细节。
- 每台主机的完整标准输出、标准错误和执行诊断写入操作日志。
- 终端结果展示本次操作日志路径，失败详情展示对应主机日志位置。

### 最终汇总

详细结果模式和简洁状态模式都必须在结束时展示：

- 成功主机数量，并列出成功主机别名与 IP。
- 失败主机数量，并列出失败主机别名与 IP。
- 每台失败主机的失败阶段和简要原因。
- 适用的单主机重试命令。

### 输出约束

- 批量命令的远程输出不得在终端中相互交错。
- 进度提示不能覆盖或破坏已完成主机的结果。
- 颜色只能辅助识别，关闭颜色后信息仍必须完整。
- 不在任何输出模式中展示密码、私钥或其他敏感凭据。

## 操作日志

### 用途

- 操作日志保存简洁状态模式隐藏的完整远程命令输出和诊断信息。
- 日志帮助核心用户在看到失败主机后进一步排查，而无需重新执行整个目标集合。
- 日志属于 sshm 数据目录的一部分，可随完整数据目录迁移。

### 日志结构

- 每次批量操作创建一个独立操作日志目录或文件。
- 日志记录操作时间、动作类型、命令或传输摘要和具体目标集合。
- 每台主机拥有独立日志段或独立文件，使用别名与 IP 标识。
- 每台主机日志记录标准输出、标准错误、失败阶段、退出状态和耗时。
- 终端最终汇总展示本次操作日志位置。

### 安全约束

- 日志不得记录主密码、SSH 密码、私钥内容或解密凭据。
- 对可能包含敏感输出的远程命令，执行前或帮助中应明确提示日志会保存完整输出。
- 日志文件权限必须限制为当前用户可读写。

### 保留与清理

- 默认保留最近 30 天的操作日志。
- 每次批量操作开始前自动清理超过保留期的日志。
- `sshm logs` 用于查看和定位历史操作日志。
- `sshm logs clean` 用于手动清理日志。
- 日志保留时间暂不提供复杂配置，待实际使用反馈后再评估。

### 目录建议

```text
<SSHM_HOME>/logs/
└── <操作时间>-<动作类型>/
    ├── summary.txt
    ├── prod-web-01-10.0.0.11.log
    └── prod-web-02-10.0.0.12.log
```

日志不额外加密，因为远程输出内容无法可靠识别和脱敏；产品必须明确提示日志可能包含敏感业务输出，并通过当前用户专属文件权限保护。

## 安全与便捷原则

### 默认行为

- 默认严格验证远程主机身份，所有 SSH 能力使用一致的主机信任策略。
- 默认加密保存密码和私钥，不在磁盘长期保留明文托管私钥。
- 默认在批量操作和可能造成远端变更的操作前展示影响范围并要求确认。
- 默认在配置、凭据或远端操作部分失败时保护原有可用状态，并提供明确恢复信息。

### 显式便捷选项

- 首次确认并信任主机指纹后，后续连接不重复询问。
- 可为脚本化或熟练用户提供明确的单次跳过确认选项，例如 `--yes`。
- 可提供缩短交互步骤的选项，但选项名称和提示必须准确表达风险。

### 不可接受的行为

- 不静默跳过主机身份验证、凭据保护或危险操作确认。
- 不静默忽略用户输入的参数。
- 不为了回退或兼容而使用更弱的安全策略。
- 不把安全失败伪装成普通连接失败或静默降级。

## 主密码会话模型

### 解锁行为

- 主密码仅在当前 sshm 进程内使用和保留。
- 工作台启动时不强制解锁；第一次需要读取或修改凭据时再请求主密码。
- 工作台成功解锁后，在当前工作台进程内保持解锁，避免重复输入。
- 别名直连和单条 CLI 命令是独立进程，每次需要凭据时独立请求主密码。

### 锁定行为

- `lock` 立即清除当前进程内已解锁的密码库状态。
- 退出进程即视为自动锁定。
- 锁定后不影响无需凭据的主机查看、搜索和配置检查能力。

### 明确非目标

- 不在后台进程中长期缓存主密码或解密凭据。
- 不提供“记住主密码”。
- 不接入系统钥匙串、凭据管理器或其他外部秘密存储保存主密码。
- 不把主密码写入配置、环境变量或数据目录。

### 提示原则

- 只在当前操作确实需要凭据时提示主密码。
- 主密码错误与具体 SSH 凭据错误应明确区分。
- 用户取消主密码输入时，应取消或降级当前操作，而不是影响无关功能。

## SSH 实现边界

### 已确认决策

- SSH 连接、认证、远程执行、主机信任和端口转发由 sshm 使用 Go 原生实现。
- 文件传输优先使用可用且适用的 `rsync` 加速；不可用或不适用时回退到 Go 原生文件传输。
- `rsync` 是可选性能优化，不是安装或使用 sshm 的必要依赖。
- `rsync` 路径必须遵守与原生路径一致的主机身份验证和凭据安全规则。
- 除文件传输的可选 `rsync` 加速外，不调用系统 `ssh` 或其他外部 SSH 工具作为兼容通道或失败回退。
- 不透传任意 OpenSSH 命令行参数。
- 托管密钥是推荐的密钥认证方式。
- OpenSSH 配置导入仅导入 sshm 原生支持且能够兑现的配置；其余配置必须明确提示并跳过。

### 产品影响

- 不同平台使用一致的连接和安全行为。
- 功能支持范围由 sshm 明确定义，而不是依赖用户机器安装的软件版本。
- 高级连接能力必须作为正式产品能力设计、实现和测试，不能通过系统命令临时兼容。
- 安装了 `rsync` 的环境可以获得更快的文件传输；未安装时仍能完成相同的基础任务。

## 文件传输语义

### 支持范围

- `push` 和 `pull` 同时支持单个文件与目录。
- 文件和目录在 `rsync` 加速路径与原生路径中保持相同的用户语义。
- 批量拉取按主机别名创建独立目录，避免不同主机的同名文件互相覆盖。

### 传输方式

- 本地与远端环境均满足条件时优先使用 `rsync` 增量传输。
- `rsync` 不可用或不适用时，自动使用 Go 原生传输完成完整复制。
- 执行结果中展示实际使用的传输方式。
- 传输方式切换不得改变主机信任、凭据保护、目标选择和覆盖规则。

### 覆盖规则

- 默认不覆盖已存在的目标文件或目录。
- 需要覆盖时，用户必须显式使用 `--overwrite` 或在交互提示中批准。
- 批量操作中，覆盖批准必须适用于执行前展示的完整目标集合，不能逐台产生不可预期提示。

### 原子性与失败恢复

- 拉取内容先写入目标目录中的临时文件或临时目录，成功后再原子替换为最终目标。
- 推送应尽可能先写入远端临时目标，成功后再替换最终目标。
- 失败、取消或超时时不留下可被误认为成功结果的半成品。
- 如果无法提供原子替换，必须在执行前明确提示风险。

### 结果展示

- 每台主机展示传输方向、源、目标、传输方式、完成状态和失败阶段。
- 批量拉取结果明确展示每台主机对应的本地保存目录。

## 高级连接能力

### 正式支持范围

#### 跳板机连接

- 主机可以指定另一台已配置主机作为跳板机。
- 跳板链路和目标链路都必须使用统一的主机信任与凭据安全策略。
- 用户应能在主机详情和连接前提示中清楚看到实际连接路径。
- 首期支持单级跳板；多级链路是否支持留待实际需求验证。

#### 本地端口转发

- 用户可以通过 sshm 建立本地端口到远端目标的转发。
- 转发规则应使用 sshm 自身定义的参数或配置模型，不透传任意 OpenSSH 参数。
- 启动时展示监听地址、目标地址和关联主机，端口占用或连接失败时给出明确原因。

#### 普通文件私钥导入

- 用户可以从普通私钥文件导入密钥。
- 导入后私钥进入 sshm 主密码保护的密码库，并成为托管密钥。
- 连接时从密码库解密到内存使用，不长期依赖或读取原始私钥文件。
- 加密私钥文件在导入时可要求输入原私钥密码；导入完成后由 sshm 主密码统一保护。
- OpenSSH 配置中的 `IdentityFile` 只有在用户明确同意导入为托管密钥后才视为可用认证配置。

### 暂不进入正式范围

- `ssh-agent` 集成。
- 远程端口转发。
- 动态 SOCKS 代理。
- 任意 OpenSSH 参数透传。
- 多级跳板链路，等待单级跳板使用反馈后再评估。

## 数据目录与迁移

### 产品承诺

- 主机配置、标签、收藏、最近使用、托管密钥元数据、密码和托管私钥均保存在同一个 sshm 数据目录中。
- 默认数据目录保持清晰、可定位，并支持通过 `SSHM_HOME` 显式指定。
- 复制或同步完整数据目录后，sshm 应能够在另一台兼容设备上继续使用。
- 数据目录内的敏感内容保持加密；目录同步本身不应要求解密。
- `doctor` 应检查数据目录完整性、文件权限和引用一致性。

### 明确非目标

- 不提供云同步。
- 不提供账号系统或自动上传。
- 不提供专用 `backup`、`restore` 或备份包格式。
- 不管理用户选择的第三方同步工具。

### 迁移约束

- 不应在数据目录之外长期存放 sshm 拥有的必要运行数据。
- 如果某项功能依赖外部状态或文件，产品必须明确展示并避免将其描述为可随目录迁移。
- 搬迁完整数据目录后，不应因绝对路径、设备特定缓存或遗漏文件导致核心数据不可用。

## 交互模型

### 三层入口

#### 交互工作台

- 无参数运行 `sshm` 时进入交互工作台，作为日常使用的主要入口。
- 工作台负责主机发现、搜索选择、最近使用、引导式配置和功能探索。
- 工作台保持轻量，不发展为复杂全屏 TUI。

#### 别名直连

- `sshm <别名|ID>` 是连接已知目标主机的最快路径。
- 别名直连应尽量少打扰用户，只在首次信任、凭据缺失或错误发生时增加必要交互。

#### 完整 CLI

- 完整 CLI 命令面向熟练用户、可重复操作和脚本化调用。
- CLI 必须明确区分交互操作与非交互操作；非交互场景不得等待不可见输入。
- 批量危险操作可以使用显式选项跳过确认，但默认保持安全确认。

### 一致性要求

- 工作台、别名直连和完整 CLI 共享同一套命令语义、能力和安全规则。
- 同一概念在所有入口使用同一名称，不保留相互冲突的旧术语。
- 帮助、自动补全、README 和错误提示由统一命令定义驱动或接受自动一致性检查。
- 不支持的输入必须明确报错，不静默忽略。

### 工作台体验原则

- 首屏优先展示最近使用、收藏、搜索和常用动作，而不是完整帮助墙。
- 用户能够随时看到当前所在层级，并用一致方式返回上一级或退出。
- 搜索选择器的大列表导航必须保证选中项可见，并展示足够的主机识别信息。
- 引导流程应允许取消，取消不应被描述为错误。

## 主机组织模型

### 正式支持

- 每台主机拥有唯一别名，作为直连和识别的主要名称。
- 一台主机可以拥有多个标签，用于描述环境、职责、地域或用户自定义维度。
- 收藏用于固定高频主机。
- 最近使用用于快速回到近期成功连接的主机。
- 搜索同时覆盖别名、地址、SSH 用户名、备注和标签。
- 批量操作通过显式主机选择、一个或多个标签或全部主机确定目标集合。

### 明确非目标

- 不恢复一台主机只能属于一个分类的单一分组模型。
- 不提供可命名、持久保存的目标集合。
- 不建设复杂层级目录、主机树或资产关系图。

### 组织原则

- 标签是主要分类方式，但不应成为连接已知主机的必要步骤。
- 收藏和最近使用用于速度，标签用于组织与批量选择，三者职责清晰。
- 目标选择结果必须在执行前展开为具体主机，避免用户只看到抽象标签而误操作。

## 添加主机流程

### 核心原则

- 添加主机是纯本地配置流程。
- 添加时不主动测试网络可达性、SSH 端口、主机身份或认证凭据。
- 服务器离线、尚未开通或当前网络不可达时，用户仍可以完成添加。
- 添加流程按步骤收集并校验本地可判断的信息，不引入远端副作用。

### 默认步骤

#### 快速添加

- 必填：唯一别名和 `SSH用户名@主机地址[:端口]`。
- 使用默认端口和 `auto` 认证策略。
- 信息校验通过后立即保存。
- 不询问密码、不连接远端、不部署密钥。

#### 工作台向导

1. 输入唯一别名。
2. 输入 SSH 用户名、主机地址和端口。
3. 可选修改默认 `auto` 认证策略。
4. 可选绑定已有托管密钥。
5. 可选保存 SSH 密码。
6. 可选填写标签和备注。
7. 展示摘要并保存主机。

除别名、SSH 用户名和主机地址外，向导中的增强配置均可跳过。

### 添加时的校验范围

- 校验别名格式与重复。
- 校验端口范围和认证策略值。
- 校验引用的托管密钥是否存在。
- 校验跳板机引用不存在循环。
- 不验证主机能否连接、密码是否正确、公钥是否已部署或远端路径是否存在。

### 后续显式动作

- `ping` 或连接操作负责验证主机可达性与认证。
- `key setup` 负责部署、验证并绑定托管密钥。
- `doctor` 负责检查本地配置和凭据引用一致性。
- 添加完成后只提示这些可选后续动作，不自动执行。

## 单主机连接与恢复

### 连接阶段

连接过程应能够区分并报告以下阶段：

1. 主机解析。
2. 网络连接。
3. 跳板机连接，如适用。
4. 主机身份验证。
5. SSH 认证。
6. PTY 或 Shell 启动。

### `auto` 认证策略

- 按明确顺序尝试已配置且可用的认证方式。
- 优先尝试绑定的托管密钥。
- 托管密钥失败后，可尝试已保存的 SSH 密码。
- 所有已配置方式失败后，在交互终端中可询问一次临时 SSH 密码。
- 非交互环境不等待临时密码输入，直接返回结构化失败信息。

### 临时密码救援

- 临时密码仅用于当前连接尝试。
- 临时密码连接成功后，可以询问是否保存该密码。
- 保存密码需要明确批准并解锁密码库。
- 不因临时密码成功而自动修改认证策略、绑定密钥或部署公钥。

### 失败恢复提示

- 失败结果明确显示失败阶段和实际尝试过的认证方式。
- 根据失败类型建议可执行动作，例如 `edit`、`passwd`、`key setup` 或重新信任主机。
- 不使用另一个更弱的连接实现静默回退。

## 产品成功标准

### 快速连接

- 已配置主机能够在几秒内通过别名直连或工作台找到并开始连接。
- 已信任且凭据可用的主机不产生不必要的重复询问。

### 安全上手

- 新用户无需手写 OpenSSH 配置，也能安全完成主机添加、主机信任和凭据设置。
- 安全失败和凭据问题具有明确、可操作的提示，不发生静默降级。

### 可控批量操作

- 执行前能够清楚确认目标集合，降低误选主机的风险。
- 执行后提供逐主机结果，任何失败都必须明确指出具体主机。
- 汇总信息不能代替逐主机失败详情。

### 逐主机失败详情契约

每个失败结果必须包含：

- 主机别名。
- SSH 用户名、主机地址和端口。
- 失败阶段，例如主机信任、连接、认证、远程执行或文件传输。
- 原始失败原因的清晰摘要。
- 用户可以采取的处理建议。
- 可以直接执行或调整的单主机重试命令。

示例：

```text
prod-web-02 (root@10.0.0.12:22)
失败阶段: SSH 认证
原因: 托管密钥被拒绝
建议: 检查远端 authorized_keys
重试: sshm exec prod-web-02 "..."
```

失败详情应在终端中清晰可读，并为未来可选的机器可读输出保留结构化字段。

### 可搬迁数据

- 复制完整数据目录到另一台兼容设备或新路径后，核心配置与加密凭据仍然可用。

### 可靠发布

- 正式发布不出现安装路径失效、数据丢失或安全策略静默降低。
- 三平台已有正式能力通过发布前回归验证。

## 平台支持策略

### 功能承诺

- Linux、macOS 和 Windows 的最终正式功能范围完全平等。
- 连接、认证、跳板机、本地端口转发、文件传输、批量操作、工作台和数据目录迁移均不得永久排除 Windows。
- 平台差异可以采用不同底层实现，但用户可见语义、安全规则和配置模型应保持一致。

### 交付优先级

- Linux 和 macOS 是主要开发与首发验证平台。
- Windows 是次要交付优先级平台，新能力可以晚于 Linux/macOS 交付。
- Windows 的延后必须是明确、临时且可追踪的，不得演变为永久缺失。
- 发布说明必须明确列出平台能力差异和已知限制。

### 发布质量

- 三个平台的已有正式能力都必须通过基础回归测试后才能发布。
- Linux 和 macOS 应覆盖主要交互与高级能力测试。
- Windows 至少覆盖安装、配置、凭据、连接和现有正式能力的自动化或人工验收。
- 平台不支持必须显式报错，不得静默失效。

## 产品路线图

路线图按“先恢复可信基础，再统一核心旅程，最后扩展能力”的顺序实施。

### 阶段 1：可信发布与数据安全

目标：确保安装、连接、传输和凭据变更不会产生已知错误、安全降级或数据不一致。

- 修复 Go 安装与版本发布路径。
- 修复 `pull` 参数语义。
- 统一所有 SSH 操作的主机身份验证。
- 修复文件传输路径、覆盖、半成品与超时处理。
- 保证密码库与主机配置的一致性。
- 加强配置版本和稳定 ID 校验。
- 清理错误帮助、README 与已废弃分组术语。

完成标准：

- 正式安装路径可用。
- 连接、执行、ping、密钥操作和传输不使用弱化的安全回退。
- 已知的数据一致性问题具有自动化回归测试。

### 阶段 2：统一核心使用体验

目标：让工作台、别名直连和完整 CLI 对同一任务表现一致，并让失败可定位、可恢复。

- 重构工作台首屏与大列表选择器。
- 统一添加主机向导。
- 统一主密码会话与取消语义。
- 统一单主机连接阶段与恢复建议。
- 统一远程操作确认策略和单次 `--yes`。
- 统一逐主机结果、失败详情、详细结果模式和简洁状态模式。
- 增加操作日志、查看和清理能力。

完成标准：

- 三个入口共享命令语义与安全规则。
- 所有批量操作都明确展示成功和失败主机及 IP。
- 简洁模式完整结果可通过日志定位。

### 阶段 3：完整文件与密钥体验

目标：让文件传输和既有私钥迁移成为可靠、易理解的正式能力。

- 文件与目录传输统一支持 `rsync` 加速和原生回退。
- 默认不覆盖，支持显式 `--overwrite`。
- 普通文件私钥导入为托管密钥。
- OpenSSH 配置导入只承诺可兑现能力。
- 改造 `key setup` 为前置检查充分、结果可恢复的工作流。

完成标准：

- 文件和目录在三平台最终具有一致语义。
- 原始私钥文件导入后可脱离原文件继续连接。
- 密钥部署部分失败时可定位并单机重试。

### 阶段 4：高级连接能力

目标：满足个人管理复杂网络环境的高价值连接需求。

- 支持单级跳板机。
- 支持本地端口转发。
- 在主机详情、连接提示和失败阶段中展示跳板与转发信息。
- 完成 Windows 对应能力，允许晚于 Linux/macOS 交付但必须追踪。

完成标准：

- 跳板链路两端都严格验证主机身份。
- 本地端口转发可可靠启动、展示和停止。
- 三平台最终功能范围平等。

### 持续质量门槛

- 每个阶段增加对应核心旅程测试，不依赖总体覆盖率数字代替行为验证。
- 每次发布验证安装、数据目录迁移、连接、凭据、批量结果和平台差异。
- 新功能必须同步更新命令帮助、补全、README、产品文档和发布说明。

## 非目标汇总

- 团队协作、账号、共享空间、审批和集中审计。
- 企业堡垒机和大型资产管理。
- 持续部署、任务编排、定时任务和配置管理。
- 云同步、专用备份包和恢复工具。
- 复杂全屏 TUI。
- 单一分组、持久化目标集合和复杂主机树。
- 任意 OpenSSH 参数透传、`ssh-agent`、远程端口转发和动态代理。
- 后台主密码缓存和系统钥匙串集成。

### 产品优先级约束

- 新能力不得显著增加日常连接目标主机所需的步骤。
- 便捷性改进不得静默降低凭据或主机身份验证的安全性。
- 批量能力必须建立在目标范围清晰、执行前确认和结果可恢复的基础上。
- 批量能力必须保持即时、一次性和用户在场，不引入后台编排系统。
