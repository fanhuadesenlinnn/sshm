# sshm Product Backlog

本文档记录截至 v5.0.0 已完成的产品与工程验收项。优先级按用户影响、安全风险和数据一致性排序。

状态说明：

- `已完成`：已通过验收

## P0

### PB-001 修复 Go 模块版本与安装路径

- 状态：已完成
- 问题：旧版 README 推荐的 Go 安装路径与主版本标签不匹配，无法安装最新正式版本。
- 用户影响：用户无法按文档通过 Go 安装最新版本。
- 解决方案：v4 使用标准 `/v4` 模块路径，并保留 `go install` 作为正式安装渠道。
- 验收标准：
  - 文档中的 Go 安装命令可以成功安装当前正式版本。
  - 安装后的 `sshm --version` 输出正式版本号。

## P1

### PB-002 修复 `pull` 参数映射

- 状态：已完成
- 问题：帮助声明 `pull <远程路径> <本地目录> <目标...>`，实现却将第一个参数当作本地路径、第二个参数当作远程路径。
- 用户影响：`pull` 按帮助使用时无法正常工作。
- 验收标准：
  - `push` 与 `pull` 的参数语义分别符合帮助说明。
  - 为两种方向添加自动化测试。

### PB-003 统一所有 SSH 操作的主机身份验证

- 状态：已完成
- 问题：普通连接、执行与 ping 严格校验 `known_hosts`，文件传输回退路径却绕过主机密钥验证。
- 用户影响：同一主机在不同命令下安全行为不一致；文件传输存在中间人攻击风险。
- 产品决策：所有能力默认使用严格、一致的主机信任策略，不允许回退路径静默降低安全性。
- 验收标准：
  - 连接、执行、ping、密钥部署和文件传输使用同一套主机信任策略。
  - 已知主机密钥变化时所有操作均拒绝连接。
  - 未知主机在非交互环境中默认拒绝。

### PB-004 重构文件传输路径与失败处理

- 状态：已完成
- 问题：远程路径直接拼入 Shell 命令；特殊字符可能导致命令失败或执行额外内容。拉取失败时可能留下空文件或半成品，超时也没有完整覆盖 SSH 读写。
- 用户影响：文件损坏、错误远程操作、安全风险和难以理解的失败结果。
- 产品决策：保留 `rsync` 作为可选加速路径，并提供 Go 原生传输回退。两条路径必须保持一致的主机身份验证、凭据安全和结果语义。
- 验收标准：
  - `rsync` 可用且适用时优先使用，并在结果中说明实际传输方式。
  - `rsync` 不可用或不适用时自动回退原生传输，不要求用户安装额外依赖。
  - `push` 和 `pull` 同时支持文件与目录。
  - 默认不覆盖现有目标；覆盖需要显式 `--overwrite` 或交互批准。
  - 路径包含空格、单引号和常见特殊字符时可正确传输。
  - 失败或超时时不覆盖目标文件、不保留半成品。
  - 拉取先写临时目标，成功后再替换最终目标。
  - 批量拉取按主机别名分目录，并明确展示保存位置。

### PB-005 解决 OpenSSH `IdentityFile` 导入后的认证落差

- 状态：已完成
- 问题：导入 OpenSSH 配置时会保存普通私钥路径，但当前连接逻辑只支持 sshm 托管密钥和保存密码。
- 用户影响：导入显示成功，实际连接却无法使用导入的私钥。
- 产品决策：用户可以明确选择将 `IdentityFile` 导入为主密码保护的托管密钥；不长期依赖原文件路径。
- 验收标准：
  - 导入成功的主机可以使用导入时承诺的认证方式连接。
  - 无法支持的配置在导入时明确提示并跳过。
  - 未经用户确认，不读取或导入 OpenSSH 配置引用的私钥文件。
  - 导入后删除或移动原私钥文件不影响连接。

### PB-006 保证密码库与主机配置的一致性

- 状态：已完成
- 问题：设置或修改密码时，密码库与主机配置分步更新；后一步失败可能导致配置引用失效或留下孤立密码。
- 用户影响：已保存密码突然不可用，恢复路径不清晰。
- 验收标准：
  - 任一步失败后，主机配置与密码库仍保持可用的一致状态。
  - 为设置、修改、删除和迁移密码增加故障注入测试。

### PB-006A 统一主密码解锁与取消语义

- 状态：已完成
- 目标：所有需要凭据的能力遵循按需解锁、当前进程复用、主动锁定和取消不影响无关功能的会话模型。
- 验收标准：
  - 工作台内第一次需要凭据时解锁一次，后续凭据操作不重复提示。
  - `lock` 后下一次凭据操作重新提示主密码。
  - 单条 CLI 命令不依赖其他进程的解锁状态。
  - 用户取消解锁时，错误信息明确且不破坏配置或凭据。

## P2

### PB-007 明确额外 SSH 参数的产品承诺

- 状态：已完成
- 问题：帮助宣称支持 `sshm <别名|ID> [SSH参数...]`，实现却静默忽略额外参数。
- 用户影响：端口转发等参数看似生效，实际未执行。
- 产品决策：不透传任意 OpenSSH 参数；删除错误帮助承诺，并对不支持的额外参数明确报错。需要的高级能力应作为 sshm 原生功能单独设计。
- 验收标准：
  - 所有接受的参数都实际生效。
  - 所有不支持的参数都明确报错，不静默忽略。

### PB-008 让 `key setup` 成为可预期的原子工作流

- 状态：已完成
- 问题：`key setup` 会先修改远端，再解锁密码库和验证密钥；后续失败时远端已经发生变化。该流程也缺少与其他批量危险操作一致的确认。
- 用户影响：用户可能在未完成绑定时修改大量远端主机。
- 产品决策：默认展示影响范围并要求显式批准；允许通过清晰的单次选项跳过确认，但不得静默跳过。
- 验收标准：
  - 执行前展示目标、动作和可能结果并要求确认。
  - 在修改远端前完成所有可执行的本地前置检查。
  - 部分失败时提供明确的恢复或重试路径。
  - 失败结果逐台列出具体主机，不以汇总数量代替详情。
  - 每台失败主机显示地址、失败阶段、原因、建议和单主机重试命令。
  - 支持单次 `--yes` 跳过执行确认，但不跳过主机信任或主密码。

### PB-009 修复主机选择器的大列表导航

- 状态：已完成
- 问题：选择器只显示前 12 项，但光标可以移动到不可见项并连接隐藏主机。
- 用户影响：主机较多时可能误连。
- 验收标准：
  - 选中项始终可见。
  - 支持滚动窗口或分页提示。
  - 增加超过 12 台主机的交互测试。

### PB-009A 重构工作台首屏与导航

- 状态：已完成
- 问题：当前无参数启动直接展示完整交互帮助，常用动作、最近主机和收藏主机不够突出。
- 产品决策：工作台是日常主要入口，但保持轻量，不发展为复杂全屏 TUI。
- 验收标准：
  - 首屏优先展示最近使用、收藏、搜索入口和常用动作。
  - 用户可以随时明确返回上一级、锁定密码库或退出。
  - 取消引导式操作不作为错误展示。

### PB-009B 统一添加主机向导

- 状态：已完成
- 目标：添加主机按步骤完成纯本地配置，不主动探测远端或产生远端副作用。
- 验收标准：
  - 离线或不可达主机可以正常添加。
  - 添加时只校验别名、端口、认证策略和本地引用。
  - 快速添加、工作台向导和批量添加遵循一致的数据语义。
  - 添加完成后明确提示可使用 `ping`、连接或 `key setup` 进行后续验证。
  - 快速添加仅要求别名和 SSH 目标，使用默认 `auto` 认证并立即保存。
  - 工作台向导的认证、托管密钥、密码、标签和备注均可跳过。
  - 添加完成后不自动连接或修改远端。

### PB-010 加强配置版本与稳定 ID 校验

- 状态：已完成
- 问题：程序不拒绝高于当前支持版本的配置，也不检查重复稳定 ID。
- 用户影响：新版本配置可能被旧程序覆盖；重复 ID 可能造成最近使用、密码引用等状态串联。
- 验收标准：
  - 高于当前支持版本的配置只读拒绝，不自动覆盖。
  - 保存和导入时拒绝重复稳定 ID。
  - `doctor` 检查数据目录内配置、凭据和托管密钥引用的一致性。

### PB-011 统一版本号、帮助和 README

- 状态：已完成
- 问题：源码构建显示 `0.2.0`；README 仍包含已删除的 group、copy、exec-group、文件私钥等命令；内置帮助也存在未实现承诺。
- 用户影响：用户无法判断真实能力和正确用法。
- 验收标准：
  - README、内置帮助、补全和实际命令保持一致。
  - 源码构建使用明确的开发版本标识。
  - CI 自动检测关键帮助示例和命令路由是否漂移。
  - 工作台、别名直连与完整 CLI 使用同一套命令术语和安全规则。
  - 清除已废弃的单一分组术语，统一使用标签。

### PB-012 补齐关键用户流程测试

- 状态：已完成
- 问题：整体语句覆盖率约 25%；连接、文件传输、批量执行、删除和编辑等关键命令接近零覆盖。
- 用户影响：高风险回归只能在用户使用时发现。
- 验收标准：
  - 为核心旅程建立端到端或高保真集成测试。
  - 发布前验证安装、首次使用、连接、批量操作、恢复与升级。
  - 验证复制完整 `SSHM_HOME` 到新路径后核心功能仍可使用。
  - 三平台已有正式能力均有发布前回归验证。
  - Windows 暂未交付的新能力必须记录为明确、临时、可追踪的平台差异。
  - 验证所有批量操作在部分失败时明确输出具体失败主机。
  - 验证逐主机失败详情包含主机身份、失败阶段、原因、建议和重试命令。

### PB-015 统一批量操作结果模型

- 状态：已完成
- 目标：命令执行、密钥部署、连接测试和文件传输共享统一的逐主机结果与失败详情模型。
- 验收标准：
  - 每个目标主机都有独立成功或失败结果。
  - 失败结果包含主机身份、失败阶段、原因、建议和重试命令。
  - 终端摘要与逐主机详情一致，不丢失部分失败信息。
  - 支持按主机依次展示完整输出的详细结果模式。
  - 支持隐藏成功主机命令输出、仅展示状态的简洁状态模式。
  - 默认使用详细结果模式，仅在显式传入 `--quiet` 时启用简洁状态模式。
  - 不根据命令内容、输出大小或耗时自动切换模式。
  - 两种模式最终均列出成功和失败主机及 IP。
  - 不同主机的远程命令输出不在终端中交错。
  - 简洁状态模式将完整标准输出、标准错误和诊断信息写入操作日志。
  - 终端汇总展示本次日志路径，失败主机可定位到对应日志。

### PB-015A 统一远程操作确认策略

- 状态：已完成
- 目标：所有远程操作根据其写入风险和目标数量使用一致的执行确认规则。
- 验收标准：
  - 单主机连接、ping 和不覆盖的单主机拉取默认无需确认。
  - 单主机命令执行、推送和远端密钥修改默认需要确认。
  - 所有多主机操作默认展开具体目标并确认。
  - `--yes` 仅跳过当前一次执行确认，不跳过其他安全控制。
  - 非交互环境中缺少必要 `--yes` 时明确失败，不等待输入。

### PB-016 统一单主机连接阶段与恢复建议

- 状态：已完成
- 目标：单主机连接失败时明确失败阶段、认证尝试与可执行恢复路径。
- 验收标准：
  - 区分主机解析、网络、跳板机、主机身份、SSH 认证和 Shell 启动失败。
  - `auto` 按明确顺序尝试托管密钥和保存密码。
  - 交互环境中所有已配置认证失败后可询问临时密码。
  - 临时密码成功后仅在用户明确批准时保存。
  - 失败信息提供适用的 `edit`、`passwd` 或 `key setup` 建议命令。

### PB-017 增加个人操作日志

- 状态：已完成
- 目标：为简洁状态模式保存完整批量执行结果，支持按操作和主机排查。
- 验收标准：
  - 操作日志保存在 sshm 数据目录中，并使用当前用户专属权限。
  - 每次批量操作和每台主机均可独立定位。
  - 日志包含标准输出、标准错误、失败阶段、退出状态和耗时。
  - 日志不记录主密码、SSH 密码、私钥或其他解密凭据。
  - 终端最终汇总展示日志路径。
  - 默认保留最近 30 天，每次批量操作前自动清理过期日志。
  - 提供 `sshm logs` 查看日志和 `sshm logs clean` 手动清理。
  - 日志不额外加密，使用当前用户专属权限，并提示可能包含敏感远程输出。

## 新能力

### PB-018 支持多文件 Deploy 工作流

- 状态：已完成
- 目标：允许核心用户通过独立 YAML 文件定义、预览并执行由 copy 和 exec 组成的轻量部署工作流。
- 验收标准：
  - 核心主机、凭据、密钥与信任继续只保存在 `sshm.yaml`。
  - 支持显式文件、全局文件、排序片段和项目文件组合，Profile 重名明确报错。
  - 支持 validate、list、show、plan、run、一次性 exec/copy、文本与 JSON 输出。
  - 同一主机内步骤串行，不同主机并发；失败、取消、超时与复制重试产生逐主机逐步骤结果和日志。
  - deploy 不提供后台调度、期望状态、条件、循环、roles、facts 或 Ansible 兼容层。

### PB-013 支持单级跳板机连接

- 状态：已完成
- 目标：允许目标主机引用另一台已配置主机作为跳板机，并通过 Go 原生 SSH 建立链路。
- 验收标准：
  - 跳板机和目标主机分别执行严格主机身份验证。
  - 两段链路可分别使用其配置的托管密钥或保存密码。
  - 主机详情与连接提示显示跳板路径。
  - 检测直接循环引用并明确报错。

### PB-014 支持本地端口转发

- 状态：已完成
- 目标：允许用户通过已配置主机建立本地端口转发，不透传任意 OpenSSH 参数。
- 验收标准：
  - 用户可以明确指定本地监听地址、端口和远端目标。
  - 启动成功后持续展示当前转发规则。
  - 本地端口占用、SSH 断开和目标不可达时给出明确错误。
  - Ctrl+C 可以可靠关闭监听与 SSH 连接。
